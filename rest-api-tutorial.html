Build a REST API with Express A step-by-step tutorial: the Quoote API In this tutorial you build a small but complete REST API for famous quotes. When you finish, any client (a browser, an API tester, later a React app) can read all quotes or one quote, create a new quote, update it, delete it, ask for a random quote, and search by author. Every reply is JSON with the right HTTP status code, and errors are handled in one place. It puts into practice the notes Introduction to REST APIs and Implementing Using Express: resources and endpoints, the four HTTP methods, query strings, headers, status codes, async/await, try/catch and error-handling middleware. It uses the same quote data and the same records.js file as the class folders S1-1 to S4-2. Part A: What a REST API is

Step 1Look at a real REST API (5 min)

A normal website sends finished HTML pages to a browser. A REST API sends only the data, usually as JSON, and lets each client build its own screen. That way one back end can serve a website, a phone app and other servers at the same time.

  1. Open Chrome and go to https://randomuser.me/api/?results=1&nat=ca
  2. Tick Pretty-print at the top of the page. You get a random (made-up) person as JSON: no HTML, no styling, only data.
  3. Reload the page. A new person arrives. The server does not remember you between requests: this is what stateless means. Every request must carry everything the server needs.
  4. Change results=1 to results=3 and press Enter. You now get three people.

The part after ? is the query string: a list of key=value pairs joined with &. Look at how a request to an API is built:

  • The resource is the kind of thing the API manages (games, players, quotes).
  • An endpoint is a URL for that resource: either the whole collection (/games) or one item in it (/games/1234).
  • The action is not in the URL. It is the HTTP method: GET reads, POST creates, PUT updates, DELETE deletes. These four actions are often called CRUD (Create, Read, Update, Delete).

Step 6GET one quote with a route parameter (5 min)

/quotes/2048 should return only the quote whose id is 2048. In Express, :id in a path is a route parameter: whatever is in that part of the URL arrives in req.params.id.

  1. Add:
// Send a GET request to /quotes/:id to READ (view) a quote
app.get('/quotes/:id', (req, res) => {
  const quote = data.records.find(q => q.id == req.params.id);
  res.json(quote);
});
  1. Open http://localhost:3000/quotes/2048.
WHY==ANDNOT===?

req.params.id is always a string ("2048") but the id in the data is a number (2048). == converts before comparing. (Number(req.params.id) === would work too.) 3. You will fix that in Step 8.

Step 8Status codes: send 404 when a quote does not exist (5 min)

The status code is how an API tells the client what happened, before the client even reads the body. The first digit gives the family:

res.status(code) sets the code, and you chain .json(...) on to it. Change the /quotes/:id
route so a missing quote gives 404 Not Found and a message:
// Send a GET request to /quotes/:id to READ (view) a quote
app.get('/quotes/:id', async (req, res) => {
  const quote = await records.getQuote(req.params.id);
  if (quote) {
    res.json(quote);
  } else {
    res.status(404).json({ message: 'Quote not found.' });
  }
});

Open http://localhost:3000/quotes/1 again: now the client gets a clear answer.

Part E: CREATE, UPDATE, DELETE

Step 10POST: create a new quote (8 min)

POST /quotes adds a quote to the collection. The new quote travels in the request body as JSON, and you read it in Express from req.body. You do not send an id: records.createQuote() makes one, just as a database would.

  1. Add this route under the GET routes:
// Send a POST request to /quotes to CREATE a new quote
app.post('/quotes', async (req, res) => {
  const quote = await records.createQuote({
    quote: req.body.quote,
    author: req.body.author
  });
  res.status(201).json(quote);
});

201 Created is the success code for "a new resource was made". It is good practice to send the new item back, so the client learns its id.

  1. In the tester: method POST, URL http://localhost:3000/quotes, open Body, choose JSON (in Postman: raw then JSON), and type:
{
  "quote": "Make it work, make it right, make it fast.",
  "author": "Kent Beck"
}
  1. Press Send. It fails!

Step 16Query strings: search by author (5 min)

Query strings are how a client adds options to a request on a collection: search, sort, filter, page. Express puts them in req.query: for /quotes?author=dijkstra, req.query.author is "dijkstra". (The class file S4-2 reads them the old way, with url.parse(req.url, true).query. req.query gives the same object with no extra code.) Change the /quotes route so ?author= keeps only matching quotes. Without ?author=, req.query.author is undefined and every quote is sent, as before.

// Send a GET request to /quotes to READ a list of quotes
// Optional query string: /quotes?author=dijkstra
app.get('/quotes', async (req, res) => {
  const data = await records.getQuotes();
  let quotes = data.records;
  if (req.query.author) {
    const search = req.query.author.toLowerCase();
    quotes = quotes.filter(q => q.author.toLowerCase().includes(search));
  }
  res.json(quotes);
});

// ------------------------------------------------ error handling
// 1. No route above matched: make a 404 error and pass it on
app.use((req, res, next) => {
  const err = new Error('Not Found');
  err.status = 404;
  next(err);
});
// 2. The error handler (4 parameters): every next(err) ends up here
app.use((err, req, res, next) => {
  res.status(err.status || 500);
  res.json({
    error: {
      message: err.message
    }
  });
});
  • Middleware runs in the order it is written. The first one is reached only if no route sent a reply, so it is a "catch-all" for unknown URLs.
  • Calling next(err) with an error skips every normal route and jumps straight to the error handler. Express recognises the error handler by its four parameters (err, req, res, next), so keep all four even if you do not use next. Now let the routes use the same handler. In each route that has a catch, add next to the parameters and replace the 500 reply with next(err). For example, DELETE becomes:
// Send a DELETE request to /quotes/:id to DELETE a quote

      res.status(204).end();
    } else {
      res.status(404).json({ message: 'Quote not found.' });
    }
  } catch (err) {
    next(err);
  }
});
