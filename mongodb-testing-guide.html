01先看懂整条链路

这个项目的每一次请求，都会沿着同一条路径走。先记住这张图，后面每一步测试其实都是在验证链路中的一环。

浏览器 / curl / Thunder Client
        ↓  HTTP 请求
Express 路由 (routes/books.js)
        ↓  Mongoose Model ( Book )
MongoDB 集合 ( bookstore.books )
        ↓  文档 _id / createdAt / updatedAt
原路返回 JSON 响应
为什么这样设计
  • Mongoose 位于路由和 MongoDB 之间：路由只写 Book.find() / Book.create()，不直接写数据库命令。
  • 所以测试要分两层：一层看 API 返回的 JSON 和状态码，另一层去 MongoDB 里看文档是否真的变了。
  • 两层都对，才算真正「连接成功」。

02准备：在 book-store-api-checkpoints 里选对文件夹

这个文件夹里每一个 step-XX-... 都是一个能独立运行的小项目，不是只给你看的片段。测试时先决定要跑哪一个。

推荐先用 final（完整版）跑通整条链路，再回到各个 checkpoint 逐个验证新增功能。

book-store-api-checkpoints/
├── step-05-connect/          只做连接 + 欢迎路由
├── step-06-schema-model/     新增 Schema / Model
├── step-07-seed/             新增 seed.js，可灌 6 本书
├── step-08-read/             新增 GET 列表 / 单本
├── step-09-create/           新增 POST
├── step-10-update/           新增 PUT
├── step-11-delete/           新增 DELETE
├── step-12-errors-and-filter/ 新增筛选 + 错误处理
├── step-13-modules/          拆成 routes/ 与 models/，加 CORS
└── final/                    最终完整版

要把同一个 MongoDB 连接串给某个 checkpoint 用，就把 final 里配好的 .env 复制过去：

cd "…/book-store-api-checkpoints/final"
cp .env.example .env      # 先在这里填好你自己的连接串

# 例：单独测试 step-08-read
cp final/.env step-08-read/.env

为什么要按文件夹逐个测
  • 每个 checkpoint 是当时功能的快照：step-05 还没有 books 接口，step-07 有数据但还没有读接口。
  • 如果直接拿 final 去测 step-05 的功能，你会误以为代码没生效。
  • 逐个测能清楚看到「这一步到底新增了哪个 API 行为」。
切换 checkpoint 的标准动作
  • 1) 进入目标 step 文件夹；2) 复制 .env；3) npm install；4) npm start；5) 测完按 Ctrl + C 再进下一个。
  • 所有 checkpoint 共用同一个 MongoDB 数据库 bookstore，测试数据会互相看到，这是正常的。

03第 1 步：注册 MongoDB Atlas 并创建免费集群

MongoDB Atlas 是 MongoDB 官方的云服务，免费层级（M0）足够本课程使用。

  1. 打开 https://www.mongodb.com/atlas ，点击 Sign Up；也可以用 Google 账号快捷注册，完成后去邮箱验证。
  2. 登录后创建一个 Project（项目），名字可以填 CSIS 3380 或 Module 8。
  3. 在项目里点击 Create a Cluster（或 Build a Database）。
  4. 选择 Free 层级 M0；云服务商保持默认，Region 选离你近的位置（例如临近城市）。
  5. Cluster Name 保持 Cluster0 或自己起一个，点 Create。集群创建需要 1–2 分钟，状态变绿后才能用。
免费集群的小特点
  • 一段时间没人访问会自动休眠，第一次连接可能多花几秒，这是正常的。
  • 同一个集群以后部署到云上也能继续用，不必重做。

04第 2 步：创建应用专用的数据库用户

这个账号是给 Node.js 程序连接数据库用的，不是你登录 Atlas 网页的账号。

  1. 左侧菜单进入 Database Access，点击 Add New Database User。
  2. Authentication 选择 Password。
  3. Username 填 bookuser（或你自己记得住的名字）。
  4. Password 自己设置一个强密码。强烈建议只用字母和数字，避免 @ : / # ? & 等符号，因为它们会出现在连接字符串里，需要额外转义。
  5. Database User Privileges 选择 Read and write to any database。
  6. 点 Add User，并把用户名、密码记在安全的地方。
用户名示例：bookuser
密码示例：  Bookstore2026   （请改成你自己的）
常见坑
  • 密码里带 @ 或 : 会导致连接串解析错误，出现 Authentication failed。
  • 如果已经用了特殊字符，需要对它做 URL 编码，例如 @ 写成 %40，: 写成 %3A。

05第 3 步：允许你的电脑访问集群

Atlas 默认拒绝所有未知 IP 的连接，所以必须把你的公网 IP 加进白名单。

  1. 左侧菜单进入 Network Access。
  2. 点击 Add IP Address。
  3. 推荐选择 Add Current IP Address，然后确认。
  4. 如果在教室或咖啡厅换网络，IP 会变；课程环境下也可以临时选 Allow Access from Anywhere，即 0.0.0.0/0。
安全提醒
  • 0.0.0.0/0 表示任何 IP 都能尝试连接，只应在练习环境使用，并且必须配合强密码。
  • 提交作业或长期使用时，请改回自己的固定 IP。
  • 如果漏掉这一步，启动服务器时会看到 MongooseServerSelectionError: Could not connect to any servers。

06第 4 步：复制连接字符串，并改成项目需要的格式

在集群页面点击 Connect → Drivers → Node.js，Atlas 会给出一段连接字符串。

把它整理成下面这种形式，注意数据库名 bookstore 必须写出来：

mongodb+srv://bookuser:Bookstore2026@cluster0.xxxxx.mongodb.net/bookstore?retryWrites=true&w=majority
片段含义要检查什么
mongodb+srv://使用 DNS SRV 发现集群节点Atlas 集群通常都是这个前缀
bookuser:Bookstore2026数据库用户名和密码替换成你在第 2 步设置的值
cluster0.xxxxx.mongodb.net集群地址必须和你 Atlas 页面显示的一致
/bookstore数据库名不要漏掉！漏掉会连到别的库，API 看起来是空的
?retryWrites=true&w=majority写入重试与确认级别保持默认即可
密码就是机密
  • 连接串里包含密码，要当密码对待：不要写进源码，不要发到聊天群，不要提交到 GitHub。
  • 它只应该出现在本地的 .env 文件里。

07第 5 步：把连接串放进 .env

推荐进入完整版文件夹操作；如果你用的是自己复制出来的 book-store-api 文件夹，步骤完全一样。

cd "…/Module 8 Serving MongoDB using REST API/book-store-api-checkpoints/final"
cp .env.example .env

用 VS Code 打开刚生成的 .env，改成下面这样（不要加引号，不要保留尖括号）：

MONGODB_URI=mongodb+srv://bookuser:Bookstore2026@cluster0.xxxxx.mongodb.net/bookstore?retryWrites=true&w=majority
PORT=3000
  • 把 Bookstore2026 换成你自己的密码。
  • 把 cluster0.xxxxx 换成你的真实集群地址。
  • 确认 /bookstore 这一段存在。
  • 不要提交 .env。项目里的 .gitignore 已经包含 .env 这一行。
为什么用 .env
  • server.js 第一行就是 require('dotenv').config()，它会把 .env 里的值放进 process.env。
  • 代码里只写 process.env.MONGODB_URI，所以换数据库时不用改代码。
  • 如果连接串写死在代码里，一 push 到 GitHub 就会泄露密码。

08第 6 步：安装依赖并启动 API 服务

在这个文件夹里打开终端，运行：

npm install
npm start

看到下面两行就说明 Express 已经连上 MongoDB，并开始监听端口：

Connected to MongoDB
Book Store API listening on http://localhost:3000

再打开浏览器访问 http://localhost:3000/ ，应该看到：

{"message":"Welcome to the Book Store API"}
为什么要先连接再监听
  • server.js 里的 start() 先 await mongoose.connect()，成功后才调用 app.listen()。
  • 如果数据库连不上，服务器会打印错误并 process.exit(1)，不会假装自己正常工作。
  • 所以看到「Connected to MongoDB」是后续所有测试的前提。
如果启动失败
  • 打印 Could not connect to MongoDB: ... 并退出：检查 .env 的路径、变量名是否拼写正确。
  • Authentication failed：用户名或密码错了，或者密码含特殊字符。
  • Server selection timed out：检查第 3 步的 IP 白名单和网络连接。

09第 7 步：写入 6 本测试图书

保持第 6 步的服务器终端不要关。再打开第二个终端，进入同一个文件夹，运行：

npm run seed

成功时输出：

Added 6 books
  • seed.js 会先执行 Book.deleteMany({}) 清空 books 集合，再插入 6 本示例书。
  • 所以每次运行 seed 都是「重置数据」，之前手动新增/修改的图书会消失。
  • 脚本最后调用 mongoose.disconnect()，否则 Node 进程不会自己退出。
为什么一定要 seed
  • 空数据库很难测试：你分不清是 API 没返回，还是数据库里本来就没数据。
  • seed 给你一组固定、可重复的数据，后面的 GET / PUT / DELETE 都能对照预期结果。

10第 8 步：在 MongoDB 端确认数据真的进去了

做两种核对方式，任选其一；推荐两种都试一遍。

方式 A：Atlas 网页。进入 Browse Collections → bookstore → books，应该看到 6 个文档，每个都有 _id、title、author、pages、fiction、createdAt、updatedAt。

方式 B：mongosh 命令行。先安装 MongoDB Shell（Atlas 集群页面 Connect → Shell 也会给出命令），然后执行：

mongosh "mongodb+srv://bookuser:Bookstore2026@cluster0.xxxxx.mongodb.net/bookstore"

use bookstore
db.books.find().pretty()
db.books.countDocuments()
db.books.find({ fiction: true }, { title: 1, _id: 0 })

一个文档长这样：

{
  _id: ObjectId('66f1a2b3c4d5e6f7890abcde'),
  title: 'Clean Code',
  author: 'Robert C. Martin',
  pages: 464,
  fiction: false,
  createdAt: ISODate('2026-11-18T...'),
  updatedAt: ISODate('2026-11-18T...'),
  __v: 0
}
  • countDocuments() 应该返回 6。
  • find({ fiction: true }, { title: 1, _id: 0 }) 应该只列出 3 本小说。
  • 集合名是 books：Mongoose 会把模型名 Book 自动变成小写复数集合名。
为什么要看 MongoDB 原生命令
  • API 返回 200 只能说明 Express 给出了响应；mongosh 看到文档才能证明 Mongoose 真的写进了数据库。
  • 以后遇到「API 成功但数据没变」的问题，这一招能快速定位是路由问题还是连接问题。

11第 9 步：准备 API 测试工具

你有两种选择，效果一样：

  • curl：命令行工具，macOS / Linux 自带；Windows PowerShell 里用 curl.exe。加上 -i 参数可以看到状态码和响应头。
  • Thunder Client / Postman：图形界面。VS Code 扩展市场搜 Thunder Client 安装，新建请求，填 Method、URL，Body 选 JSON，点 Send。

所有请求都基于同一个地址：

http://localhost:3000
  1. 确认服务器终端仍在运行，并显示 Connected to MongoDB。
  2. 先做一次 GET /api/books，从返回结果里复制一个 _id，后面 PUT / DELETE 会用到。
  3. 建议按顺序做：读取 → 筛选 → 创建 → 更新 → 删除；每做完一步都回到 mongosh 看一眼数据库。

12第 10 步：按顺序测试 6 个接口

下面每一条都可以直接复制到终端执行。把 <ID> 换成你上一步复制的真实 _id。

① 读取全部图书（GET）

curl -i http://localhost:3000/api/books
  • 预期状态：200 OK。
  • 预期结果：6 个图书对象的数组，并按 title 升序排列（代码里是 .sort({ title: 1 })）。
  • 响应头里有 Content-Type: application/json。

② 按小说类型筛选（GET + 查询字符串）

curl -i "http://localhost:3000/api/books?fiction=true"
  • 预期状态：200 OK，只返回 3 本 fiction 为 true 的书。
  • ?fiction=false 则返回另外 3 本。

③ 读取单本图书（GET + 路径参数）

curl -i http://localhost:3000/api/books/<ID>
  • 预期状态：200 OK，返回那一个对象。

④ 创建一本新书（POST）

curl -i -X POST http://localhost:3000/api/books \
  -H "Content-Type: application/json" \
  -d '{"title":"The Pragmatic Programmer 2nd","author":"David Thomas","pages":416,"fiction":false}'
  • 预期状态：201 Created。
  • 响应里会有新生成的 _id 和时间戳。把这个新 _id 记下来，下一步用它。
  • 如果没有加 -H "Content-Type: application/json"，Express 读不到 req.body，会返回校验错误。

⑤ 更新这本书（PUT）

curl -i -X PUT http://localhost:3000/api/books/<NEW_ID> \
  -H "Content-Type: application/json" \
  -d '{"title":"The Pragmatic Programmer 2nd","author":"David Thomas","pages":420,"fiction":false}'
  • 预期状态：200 OK，返回更新后的对象，pages 变成 420。
  • 代码用了 returnDocument: 'after'，所以拿到的是更新后的版本；runValidators: true 让 Schema 规则在更新时依然生效。

⑥ 删除这本书（DELETE）

curl -i -X DELETE http://localhost:3000/api/books/<NEW_ID>
  • 预期状态：204 No Content，没有响应体，这是正常的。
  • 再执行 GET /api/books，应该又回到 6 本书。
为什么要看状态码而不只看内容
  • 201 表示资源被创建，204 表示成功但没有内容可返回，404 表示找不到资源。
  • 状态码让前端不用解析 JSON 就能判断请求结果，是 REST API 的通用语言。

13第 11 步：故意制造错误，验证错误处理

一个可靠的 API 不仅要能成功，还要能「体面地失败」。下面每组测试都故意写错：

测试请求预期状态你会看到的错误
GET /api/books/123400That is not a valid book id.（_id 不是合法的 ObjectId，CastError）
GET /api/books/000000000000000000000000404Book not found.（格式合法但不存在）
POST /api/books body: {"title":"No author","pages":100}400ValidationError: Book validation failed: author: Path `author` is required.
POST /api/books body: {"title":"Bad","author":"X","pages":0}400ValidationError: pages must be at least 1
GET /not-a-route404{"error":{"message":"Not Found"}}

示例：

curl -i http://localhost:3000/api/books/123
curl -i -X POST http://localhost:3000/api/books \
  -H "Content-Type: application/json" \
  -d '{"title":"No author","pages":100}'
为什么 CastError 变 400，而不是 500
  • 非法 _id 和缺字段都是客户端输入问题，属于 400 Bad Request；服务器本身没坏。
  • server.js 末尾的四参数错误处理中间件统一捕获 next(err)，并把 CastError / ValidationError 转成 400，其他错误默认 500。
  • 这样前端收到的错误格式永远一致：{ error: { message } }。

14第 12 步：回到 mongosh，确认 API 的写操作真的落库

在第 10 步做 POST / PUT / DELETE 的间隙，切回 mongosh 执行：

use bookstore
db.books.find({ title: 'The Pragmatic Programmer 2nd' }).pretty()
db.books.countDocuments()
  • POST 之后：能查到这本新书，countDocuments() 变成 7。
  • PUT 之后：同一本书的 pages 变成 420，updatedAt 变新。
  • DELETE 之后：再查不到它，countDocuments() 回到 6。
这才叫「测试通过」
  • API 返回 201/200/204 是一层证据；数据库里的数据同步变化是第二层证据。
  • 两层都对，才能确认 Express → Mongoose → MongoDB 这条链路完全打通。

15第 13 步：遇到问题时的排查清单

现象最可能的原因怎么修

代码 push 后密码泄露.env 被提交到了 GitHub立刻在 Atlas 轮换密码 / 删除旧用户，并把 .env 加入 .gitignore

快速自检命令：

node -e "require('dotenv').config(); console.log(process.env.MONGODB_URI ? 'URI loaded' : 'URI MISSING')"
npm start
