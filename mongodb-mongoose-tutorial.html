Part A: How MongoDB stores data

Step 1Documents, collections, databases (10 min)

You already know SQL (relational) databases: data sits in tables, every row has the same columns, and you query it with the SQL language. MongoDB is a NoSQL database: it stores documents, which look like the JSON objects you send from an API, and groups them in collections.

A few things to notice:

  • A document is a set of field: value pairs, like a JavaScript object. Values can be strings, numbers, booleans, dates, arrays and nested objects.
  • MongoDB stores documents as BSON (binary JSON), so it also knows types JSON does not have, such as ObjectId and Date.
  • Every document gets a unique _id, an ObjectId such as 6afd4979ae906cdf708e8f47. You never have to create ids yourself.
  • MongoDB itself does not force documents to look alike. That is flexible, but risky: a typo such as titel would be saved without a word. In Step 6, Mongoose adds the rules.

  • insertOne({...}) saves one document and answers with its new _id; insertMany([...]) saves several.
  • find() returns every document. The first argument is a filter: { fiction: true } means "where fiction is true". The second (optional) is a projection: which fields to show.
  • Operators start with $: { pages: { $gt: 400 } } means "more than 400 pages" ($lt is less than, $gte and $lte include the value). .sort({ pages: -1 }) sorts from most to fewest.
  1. Update and Delete:
  • updateOne(filter, { $set: {...} }) changes only the fields inside $set. Without $set, the update would replace the whole document.
  • deleteOne(filter) removes the first match; deleteMany(filter) removes every match (deleteMany({}) empties the collection).

Step 5Connect, then listen (6 min)

Create server.js. The rule is simple: connect to MongoDB first, then start listening. An API that cannot reach its database should not pretend to work.

// Book Store API: Express + MongoDB + Mongoose
require('dotenv').config({ quiet: true });   // reads .env into process.env
const express = require('express');
const mongoose = require('mongoose');
const app = express();
const port = process.env.PORT || 3000;
app.use(express.json());   // reads JSON request bodies into req.body
// A first route, to check the server is up
app.get('/', (req, res) => {
  res.json({ message: 'Welcome to the Book Store API' });
});
// Connect to MongoDB first; only then start listening for requests
async function start() {
  try {
    await mongoose.connect(process.env.MONGODB_URI);
    console.log('Connected to MongoDB');
    app.listen(port, () => {
      console.log(`Book Store API listening on http://localhost:${port}`);
    });
  } catch (err) {
    console.error('Could not connect to MongoDB:', err.message);
    process.exit(1);
  }
}

Step 6: The schema and the model (7 min)

Add this to server.js, under the require lines and above const app = express();:

// A schema describes what every book document must look like
const bookSchema = new mongoose.Schema(
  {
    title: { type: String, required: true, trim: true },
    author: { type: String, required: true, trim: true },
    pages: { type: Number, required: true, min: 1 },
    fiction: { type: Boolean, default: false }
  },
  { timestamps: true }   // adds createdAt and updatedAt
);
// The model is the tool we use to read and write the "books" collection
const Book = mongoose.model('Book', bookSchema);

Appendix: Put the API online (Render) When the API works locally, you can host it for free so a deployed React app can use it.

  1. Push the project to a GitHub repository. Check that .env and node_modules/ are not in it.
  2. On render.com, create a Web Service from that repository with: Setting Value Runtime Node Build Command npm install Start Command node server.js (not npm start: --watch is for development) Environment variables MONGODB_URI = your Atlas connection string (Render sets PORT itself)
  3. In Atlas › Network Access, allow 0.0.0.0/0, because Render's addresses change.
  4. Deploy, then open https://<your-service>.onrender.com/api/books. The free plan sleeps when idle, so the first request after a break can take about a minute. Other hosts (Vercel, Railway, Fly.io) follow the same idea: the code from GitHub, the secret as an environment variable, and Atlas allowing the host to connect.
